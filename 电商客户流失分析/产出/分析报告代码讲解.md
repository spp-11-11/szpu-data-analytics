## 第 2 步：查缺失、查重复、看目标分布（cell 8）

```python
print(df.isnull().sum()[df.isnull().sum()>0])   # 每列有多少空值
print('完全重复的行数：', df.duplicated().sum())
print(df[TARGET].value_counts())               # 留存/流失各多少人
print('流失率：%.2f%%' % (df[TARGET].mean()*100))
```

名词和原因：

- **缺失值**：就是空格子。模型不能吃空值，所以必须决定"填掉"还是"删掉"。
- `isnull().sum()` = 数每列有多少个空格子。这里发现会话时长、邮件打开率、账户余额三列有缺失。
- **重复行**：`duplicated().sum()` 数完全一样的记录有 244 条。为什么要重视？如果同一条客户记录一条进了训练集、一条进了测试集，等于**考试时把原题泄露给了学生**，测出来的分数虚高，不可信。
- `value_counts()` = 数每类有多少个。结果留存 28749、流失 11701。
- `mean()` 为什么就是流失率？因为 `Churned` 只有 1（流失）和 0（留存），所有数加起来就是流失人数，除以总人数就是比例——**0/1 数据的平均值 = 1 所占的比例**。这里 28.93%。
- **为什么查分布**：留存占 71%，意味着一个"无脑全猜留存"的模型准确率就有 71%，但一个流失客户都找不到。所以后面**绝对不能只看准确率**，这就是引入 AUC 和召回率的原因。

## 第 3 步：找异常值（cell 11）

```python
df.loc[~df['Total_Purchases'].astype(str).str.fullmatch(r'[\d.]+'), 'Total_Purchases'].head(5)
```

这行在干嘛？`fullmatch(r'[\d.]+')` 是一个**正则表达式**——一种"按模式找字符串"的工具。`[\d.]+` 的意思是"只由数字和小数点组成"。前面加 `~` 表示取反，也就是**找出那些不是纯数字的格子**。结果揪出了 `13.0次`、`$159.94` 这种"数字被包在字符串里"的脏数据。

同时还查到：`Gender` 里混了 `F`、`1`；`Country` 里有 `usa ` 这种大小写和空格问题；`Age` 最大 200（字典规定 0~65），比率列出现负数或超过 100 的值。**这些都是录入错误，必须修，否则模型会被带偏。**

### 清洗做的四件事（整体印象）

| 脏数据现象 | 例子 | 处理方法 |
|---|---|---|
| 数字被包在文字里 | `13.0次`、`$159.94` | 正则把数字抠出来，转成真正的数字 |
| 类别写法不统一 | `F`/`Female`/`1`、`usa `/`USA` | 去空格 + 统一映射 |
| 数值超出合理范围 | `Age=200`、比率 >100 或 <0 | 先改成缺失值 NaN |
| 缺失值 | 会话时长、邮件打开率、账户余额 | 用中位数填掉，一行都不删 |

## 第 4 步：真正执行清洗（cell 14）——逐行拆

```python
data = df.copy()
```
`copy()` 是**复制一份**。后面所有修改只作用于副本 `data`，原始的 `df` 原封不动，方便前后对比。

```python
data[col] = pd.to_numeric(
    data[col].astype(str).str.extract(r'([-+]?\d+\.?\d*)')[0],
    errors='coerce')
```
这是最关键的一行，分四层看：

- `astype(str)`：先把这列当成文字；
- `str.extract(r'([-+]?\d+\.?\d*)')`：**正则提取**，括号里是匹配规则——`[-+]?` 表示可有可无的正负号，`\d+` 表示至少一个数字，`\.?` 是可有可无的小数点，`\d*` 是小数点后的数字。合起来就是"把字符串里那段数字抠出来"：`13.0次`→`13.0`，`$159.94`→`159.94`；`[0]` 是取结果的第一列；
- `pd.to_numeric(...)`：把抠出来的文字转成真正的数字；
- `errors='coerce'`：实在转不了的（比如纯字母）就填成 `NaN`（缺失值标记）。

**为什么必须做这一步？** 如果不做，`13.0次` 和 `$159.94` 会被当成两个"类别"，后面独热编码时会为每一种字符串生成一个新列，特征从约 70 列爆炸到一万五千多列，模型又慢又被噪声带偏。这是整个项目最重要的坑。

```python
data['Gender'] = data['Gender'].astype(str).str.strip().replace({'F':'Female','1':'Male'})
```
`strip()` 去掉首尾空格，`replace({...})` 按映射表替换：`F`→`Female`、`1`→`Male`。同理国家名先转小写再查映射表，查不到就用 `title()` 把首字母大写。这样 `usa `、`USA`、`usa` 三种写法归并成一种。

```python
data.loc[(data['Age']<0)|(data['Age']>65), 'Age'] = np.nan
```
`loc` 是"按条件定位"，`|` 是逻辑"或"。意思是：年龄小于 0 或大于 65 的，全部改成 `NaN`——**先当作缺失**，下一步统一处理。

```python
for col in NUM_COLS:
    if data[col].isna().sum() > 0:
        med = data[col].median()       # 求中位数
        data[col] = data[col].fillna(med)
```
`median()` 是**中位数**（把所有数排序后站中间的那个），`fillna()` 是"用某值填补空缺"。**为什么用中位数不用平均数（均值）？** 因为均值怕极端值——比如 5 个人的年龄是 20、22、24、26、200，均值是 58.4，中位数是 24，显然 24 更能代表"典型客户"。用中位数填不会被录入错误带偏。结果：清洗后 0 缺失，40450 行一行不少。

## 第 5 步：EDA 探索性分析（cell 20~32）

**名词解释**：EDA = Exploratory Data Analysis（探索性数据分析），就是正式建模前"先看看数据里藏着什么规律"。它不训练模型，只画图、算统计量。报告里一共 5 张图，每张回答一个不同问题：

| 图 | 代码单元格 | 回答的问题 | 关键代码 |
|---|---|---|---|
| 目标分布（柱+饼） | cell 20 | 流失客户占比多少？ | `data[TARGET].map({0:'留存',1:'流失'})` |
| 数值分布密度图 | cell 23 | 哪些数值特征能把两类客户分开？ | `sns.histplot(..., kde=True)` |
| 类别流失率柱状图 | cell 26 | 哪一类人更容易流失？ | `data.groupby(col)[TARGET].mean()` |
| 相关性热力图 | cell 29 | 哪些数字跟流失一起变？ | `data[NUM_COLS+[TARGET]].corr()` |
| 重点特征箱线图 | cell 32 | 流失客户的购买行为差在哪？ | `sns.boxplot(...)` |

### ① 目标分布图（cell 20）

`map({0:'留存',1:'流失'})` 是把冷冰冰的 0/1 换成中文标签，画图更直观。`value_counts()` 数两种各多少人。`pie()` 画饼图。读图结论：流失 28.9%，**中度不平衡**——这个数字直接决定了后面必须用 AUC 和召回率，不能只看准确率。

### ② 数值分布图（cell 23）

`histplot` 画直方图，`kde=True` 加一条**核密度曲线**（可以理解成把直方图抹平成的平滑曲线，看数据密集在哪）。`stat='density'` 让纵轴是密度而不是人数，这样两组人数不同也能直接比形状。`alpha=0.5` 是半透明，两组叠一起能看清。**读法**：两条曲线错位越大，这个特征越能区分流失与留存；重叠越多越没用。

### ③ 类别流失率图（cell 26）

`groupby(col)[TARGET].mean()` 是"按某列分组，对目标列求平均"。因为 1=流失、0=留存，**0/1 的平均值就是流失比例**（10 人里 3 人流失，和=3，均值=0.3=30%）。`City` 那一段特殊处理：`g[g['count']>200]` 先过滤掉样本数少于 200 的城市（人少的组比例乱跳，不可信），再 `head(5)`/`tail(5)` 只取流失率最高和最低的各 5 个。

### ④ 相关性热力图（cell 29）

`corr()` 一次性算出所有数值列两两之间的**皮尔逊相关系数**（-1 到 +1 的数，越接近 1 表示"同增同减"越强，越接近 -1 表示"你增我减"越强，接近 0 表示没直线关系）。`sns.heatmap` 把它画成颜色格子，`annot=True` 在格子里写数字，`cmap='coolwarm'` 是蓝到红配色。`corr[TARGET].drop(TARGET).abs().sort_values(ascending=False)` 意思是：取出"与流失的相关性"那一列、去掉目标自己（自己和自己相关=1，没意义）、取绝对值（不管正负只看强弱）、从大到小排。

### ⑤ 重点特征箱线图（cell 32）

`boxplot` 画的箱子：箱子上下边是第 25/75 百分位，中间横线是**中位数**（排序后正中间的数），箱子外的点是异常值。`focus` 选了"距上次购买天数"和"总购买次数"两个字段深挖。打印的分组均值显示：流失客户距上次购买 34.81 天、留存只有 25.25 天；流失客户购买 11.36 次、留存 13.83 次——**活跃度衰减是流失的先行信号**，这就是业务解释的落点。

> **EDA 总结论**：特征之间有关系、但都不是"一眼就能分干净"的强关系，所以需要让模型去学复杂的组合规律——这就是下一步建模的理由。

## 第 6 步：特征工程与切分数据集（cell 36）

```python
model_data = data.drop_duplicates().reset_index(drop=True)
```
`drop_duplicates()` 删除完全重复的行（前面查到 244 条重复，加上异常值处理产生的，共去掉 416 行，剩 40034 行）。**为什么现在才删？** 清洗阶段保留全部行号和原始表对应；建模时才去重，防止同一条样本同时进训练和测试造成"泄题"。`reset_index(drop=True)` 是把行号重新从 0 排整齐。

```python
def make_features(d):
    X = pd.get_dummies(d.drop(columns=[TARGET]), columns=CAT_COLS, drop_first=True).astype(float)
    return X, d[TARGET].astype(int)
X, y = make_features(model_data)
```

这里两个核心名词：

- **特征矩阵 X**：喂给模型的"题目"，也就是所有用于预测的列（不含答案）。
- **目标向量 y**：标准答案，就是 `Churned` 列。

`d.drop(columns=[TARGET])` 是把答案列拿掉——**题目里绝不能夹带答案**。`get_dummies` 做**独热编码**：模型只认识数字，不认识 `Male`/`USA`，所以把类别列拆成一堆 0/1 列，比如 `Gender` 拆成 `Gender_Male`、`Gender_Other`。`drop_first=True` 是丢掉每组的第一列（比如 `Gender_Female`），因为"不是男、不是其他"自然就是女，留着三列会造成信息重复（这叫**虚拟变量陷阱/完全共线性**）。结果 65 列。

### 独热编码 + 列对齐（最容易出错的两个点）

```text
原始类别列 Gender: [Female, Male, Other]
        ↓ get_dummies(drop_first=True)
Gender_Male   Gender_Other
    1              0      ← Female（两列都不是，就是被丢掉的第一类）
    0              1      ← Other
    0              0      ← Male
        ↓ 验证集也要做同样的编码，再强行对齐训练集列
X_val = X_val.reindex(columns=X.columns, fill_value=0)
```
验证集如果少了某个城市、多了某个取值，编码出的列会和训练集对不上，`reindex` 保证**列的顺序和数量完全一致**，缺的补 0、多的丢弃，否则模型会读错位置或报错。

### 切分数据

```python
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=RANDOM_SEED)
```

`train_test_split` 是把数据切成两份：**训练集**（拿来学习规律，占 80%）和**测试集**（藏着答案不参与训练，最后拿来考试，占 20%）。就像学生不能拿考题复习，`X_test` 从头到尾不参与训练和调参，这样测出来的分数才代表"预测新客户"的真实能力。`stratify=y` 是**分层抽样**：保证切完后训练集和测试集的流失比例都约 28.9%，否则随机一切可能让某一边流失户特别多，评估失真。

## 第 7 步：定义 6 种模型 + 5 折交叉验证（cell 39）

**先讲"模型"是什么**：模型就是一种"从题目 X 猜答案 y"的规则，不同算法 = 不同的猜法。代码里定义了 6 种：

| 代码 | 中文名 | 猜法（大白话） | 特点 |
|---|---|---|---|
| `LogisticRegression` | 逻辑回归 | 画一条直线把两类分开 | 简单快，但只能学直线规律 |
| `DecisionTreeClassifier` | 决策树 | 一连串"是/否"问题，像流程图 | 能学复杂规则，但容易钻牛角尖 |
| `RandomForestClassifier` | 随机森林 | 造很多棵树一起投票 | 多棵树投票，比单棵树稳 |
| `SVC` | 支持向量机 | 找一条最宽的"隔离带" | 适合复杂边界，要配标准化 |
| `KNeighborsClassifier` | KNN 近邻 | 看最近的 5 个邻居多数是啥 | 简单但慢，怕数值尺度不一 |
| `GradientBoostingClassifier` | 梯度提升 | 一棵树改一棵树的错，接力纠错 | 通常精度最高，本项目胜出 |

**为什么要试 6 种？** 没有哪种算法对所有数据都最好，只能都试一遍让数据说话。任务书要求至少 4 种，这里做了 6 种更充分。

### 标准化和 Pipeline

```python
'逻辑回归': Pipeline([('scaler',StandardScaler()),('clf',LogisticRegression(...))])
```

`StandardScaler` 标准化 = 把各列数值压缩到同一尺度（均值 0、方差 1）。为什么需要？`Lifetime_Value` 是上千的量级，`Age` 只有几十，不处理的话逻辑回归、SVM、KNN 这些"算距离"的算法会被大数值列完全主导。`Pipeline` = 把"标准化 + 模型"打包成一个整体，**保证标准化只在每一折的训练部分计算**，不会偷看验证集——这叫防止**数据泄漏**。

### 5 折交叉验证

```text
把训练集切成 5 份： [折1][折2][折3][折4][折5]

第1轮：训练 2+3+4+5 → 考 折1
第2轮：训练 1+3+4+5 → 考 折2
第3轮：训练 1+2+4+5 → 考 折3
第4轮：训练 1+2+3+5 → 考 折4
第5轮：训练 1+2+3+4 → 考 折5

最后把 5 次成绩取平均 → 每条数据都当过一次"考题"，比切一次稳
```

**为什么不用一次切分？** 一次切分碰运气：可能刚好把难分的样本都切到测试集，分数虚低；也可能都切到训练集，分数虚高。5 折轮流考，结果更可信。

```python
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=RANDOM_SEED)
scoring = {'准确率':'accuracy','精确率':'precision','召回率':'recall','F1':'f1','AUC':'roc_auc'}
res = cross_validate(model, X_train, y_train, cv=cv, scoring=scoring, n_jobs=-1)
```

`cross_validate` 是 sklearn 提供的"自动做 5 折交叉验证"的函数，帮你把上面那张图的过程跑完并算好各项得分。`n_jobs=-1` 是用电脑所有 CPU 核心并行计算，加快速度。结果表 `cv_results` 按 AUC 排序，梯度提升胜出（AUC 0.9096），进入下一步调参。

`shuffle=True` 是先把数据打乱再切折，避免数据本身有排列规律（比如前一半全是留存）导致某一折全是同一类。

## 第 8 步：调参数（cell 48 / 51）

**"参数"是什么？** 模型里有一些需要人提前设定的"旋钮"，比如树有多深、学多快。默认值不一定最适合你的数据，所以要"调旋钮"找最优组合。

```python
param_grids = {
    '梯度提升': {'n_estimators':[100,200], 'learning_rate':[0.05,0.1], 'max_depth':[2,3,4]},
}
grid = GridSearchCV(models[best_name], param_grids[best_name], scoring='roc_auc', cv=cv, n_jobs=-1)
grid.fit(X_train, y_train)
```

- `n_estimators` = 树的数量（越多越稳但越慢）；
- `learning_rate` = 每棵树纠正错误的步长（小步慢走更稳）；
- `max_depth` = 树最多能问几层问题（越深越复杂，太深会死记硬背训练数据，叫**过拟合**）。

`GridSearchCV`（**网格搜索**）就是把这三个旋钮的所有组合（2×2×3=12 种）都试一遍，每种都做 5 折交叉验证，选 AUC 最高的那组。结果是 `lr=0.1, depth=4, n=100`，AUC 0.9123。

**随机搜索（cell 51）** 是补充对比：不穷举所有组合，而是随机抽 12 组试。经验上真正关键的往往只有少数几个参数，随机采样能用更少的计算量找到接近最优的解。这里它做随机森林，AUC 0.9066，不如梯度提升，所以主模型仍选梯度提升。

**控制变量思想**：两组搜索都用同一个 `cv`、同一份 `X_train`，这样分数才有可比性——这是老师很可能追问的一点。

## 第 9 步：测试集最终评估（cell 54 / 57 / 60 / 63）

调完参后，用从没见过的测试集做最终考试。这里就是"用什么指标、为什么用"的核心。

### 混淆矩阵：四个指标都从这四个格子算出来

```text
                    预测留存      预测流失
实际留存    TN=真阴性       FP=假阳性（误报）
实际流失    FN=假阴性（漏判） TP=真阳性

准确率 = (TP+TN) / 全部
精确率 = TP / (TP+FP)   → 我报出来的"流失"里有多少是真的
召回率 = TP / (TP+FN)   → 所有真流失里我抓到了多少
F1     = 精确率和召回率的调和平均
AUC    = ROC 曲线下面积，不依赖阈值
```

### 为什么选这些指标、不选别的？

- **准确率为什么不够**：留存占 71%，一个"全猜留存"的傻模型准确率就有 71%，但它一个流失客户都抓不到。在不平衡数据上准确率会骗人，所以只作参考。
- **精确率**（0.8755）：我报出来的"流失客户"里，真流失的占多少。它低了意味着优惠券发给了一堆不会流失的人，浪费钱。
- **召回率**（0.6958）：所有真会流失的人里，我抓到了多少。它低了意味着漏掉大量即将跑掉的客户——电商场景里**漏判的代价通常远大于误报**，所以报告里强调优先看召回率。
- **F1**（0.7753）：精确率和召回率是"跷跷板"，一个高了另一个往往低。F1 是它们的调和平均，**只要有一边很差 F1 就低**，所以适合作综合主指标。
- **AUC**（0.9015）：ROC 曲线下面积。它**不依赖阈值**，衡量"模型把流失客户排在留存客户前面的能力"，0.5 是瞎猜、1 是完美。因为类别不平衡，AUC 比准确率稳健，所以前面选模型时用它排序。

### 评估代码逐行

```python
y_pred = best_model.predict(X_test)              # 直接给 0/1 答案
y_prob = best_model.predict_proba(X_test)[:,1]   # 给"流失概率"，如 0.83
print(classification_report(y_test, y_pred, target_names=['留存','流失']))
```

`predict` 输出的是硬分类（0 或 1），`predict_proba` 输出的是概率（模型有多确信）。`[:,1]` 是取"判为流失"那一列的概率。**为什么要概率？** 因为阈值可以调（后面 v2 就靠它），而且 ROC/AUC 需要概率才能算。`classification_report` 一次性打印精确率、召回率、F1、样本数。

```python
cm = confusion_matrix(y_test, y_pred)
TN, FP, FN, TP = cm.ravel()
```

`confusion_matrix` 生成上面那张四格表，`ravel()` 把它拉平成一个长度为 4 的数组，顺序正好是 TN、FP、FN、TP。

**ROC 曲线（cell 60）**：横轴 FPR（把留存错认成流失的比例），纵轴 TPR（就是召回率）。把每个模型在不同阈值下的表现连成线，越靠左上角越好，中间虚线是瞎猜。AUC 就是这条线下的面积。

**排列重要性（cell 63）**：

```python
result = permutation_importance(best_model, X_test, y_test, scoring='roc_auc', n_repeats=8, ...)
```

它干嘛？把某一列的数据**随机打乱**（破坏它和答案的关系），看模型 AUC 掉多少——掉得越多说明模型越依赖这个特征。`n_repeats=8` 是重复打乱 8 次取平均，更稳。结果客服通话次数最重要（0.1458）。注意：重要性强不等于因果，只是模型"最看重它"。

## 第 10 步：算法优化 v2（cell 67 / 70 / 72）

**为什么优化？** v1 的召回率只有 0.6958，漏判 704 个流失客户。目标：**误报不增加的前提下，多抓回一些流失客户。**

### ① 换更强的算法（cell 67）

引入 XGBoost、LightGBM 等工业界常用的升级版梯度提升，和 v1 基线在**完全相同的数据划分、同一个 cv** 下公平对比（控制变量）。LightGBM 用"直方图分桶 + 优先长最有效的叶子"，更快更准；它的 F1 和召回率略胜基线。

### ② 调参 + 调阈值（cell 70）

```python
grid_lgb = GridSearchCV(lgb, {'n_estimators':[200,400], 'learning_rate':[0.03,0.06],
    'num_leaves':[15,31], 'min_child_samples':[20,40]}, scoring='roc_auc', cv=cv, ...)
```

`num_leaves` = 叶子数（越多越复杂，太容易过拟合），`min_child_samples` = 每个叶子的最少样本数（相当于给树踩刹车，防止死记）。小学习率配多棵树更稳。选中的是 `lr=0.03, n=400, num_leaves=15, min_child=40`。

**阈值 0.39 是怎么来的？** 这是最容易被追问的亮点：

```python
oof = cross_val_predict(grid_lgb.best_estimator_, X_train, y_train,
                        cv=cv, method='predict_proba', n_jobs=-1)[:,1]
ths = np.arange(0.30, 0.61, 0.01)
oof_f1 = [f1_score(y_train, (oof>=t).astype(int)) for t in ths]
best_th = ths[int(np.argmax(oof_f1))]     # 取 F1 最大的阈值 = 0.39
```

模型默认阈值 0.5（概率≥0.5 才算流失）。代码把阈值从 0.30 到 0.60 每隔 0.01 试一遍，挑 F1 最高的 0.39——相当于把"报警线"放低一点，多抓流失客户。

**为什么不直接拿测试集调阈值？** 那叫**数据泄漏**：测试集就变成了第二个训练集，报出的 F1 虚高，换批新客户就失效。正确做法是用 **OOF（out-of-fold，折外预测）**：对训练集做 5 折，每条数据都由"没见过它的模型"预测出一个概率，在这些"干净概率"上挑阈值，再原封不动用到测试集。

### 怎么判断 v2 到底好不好？（cell 72）

在同一测试集、同一口径下比：

| 指标 | v1 基线 | v2 优化 | 变化 |
|---|---:|---:|---:|
| AUC | 0.9015 | 0.9053 | +0.0038 |
| F1 | 0.7753 | 0.7795 | +0.0042 |

提升不大但方向一致，且同一数据同一口径，结论可信。要诚实指出：0.004 级提升不是质的飞跃——全班同学 F1 集中在 0.779~0.798，极差才 0.018，已接近这份数据的天花板。

## 第 11 步：输出最终预测（cell 77 和 cell 75）

```python
final_model = grid.best_estimator_.fit(X, y)   # 用全部训练数据重新训练
```

**为什么全量重训？** 调参和交叉验证时为了评估，每次只用了 80% 的训练数据。确定最优参数后，用**全部** 40034 行重训一次，让模型看到最多信息。

```python
X_val = pd.get_dummies(val_clean, columns=CAT_COLS, drop_first=True).astype(float)
X_val = X_val.reindex(columns=X.columns, fill_value=0)   # 列对齐
pred_val = final_model.predict(X_val).astype(int)
result = pd.DataFrame({'行号':np.arange(len(val_clean)), '预测是否流失':pred_val})
result.to_csv('prediction_result.csv', index=False, encoding='utf-8-sig')
```

验证集 `测试集.csv` 没有答案列，先用和训练集**完全相同**的规则清洗（正则提数字、类别归一、越界置空中位数填充），再做独热编码。关键点：

- `reindex(columns=X.columns, fill_value=0)`：验证集独热编码出来的列可能和训练集不一致（比如某个城市验证集里没出现），强行按训练集的 65 列对齐，缺的补 0、多的丢弃——否则模型会读错位置或报错。
- `np.arange(len(val_clean))` 生成 0~4999 的行号，保证结果能和验证集逐行核对。
- `encoding='utf-8-sig'` 是带 BOM 的 UTF-8，Excel 打开中文列名不乱码。
- 对**全部 5000 行**预测，不抽样。
- v2 同理另存 `prediction_result_v2.csv`，**不覆盖** v1，方便对比。

## 一页纸总结（口试可以这样答）

**整个流程**：读数据 → 查缺失/重复/异常 → 清洗（字符串提数、类别归一、越界置空、中位数填充，不删行）→ EDA 五张图找规律 → 独热编码 + 分层切分 + 建模前去重 → 6 种模型 5 折交叉验证按 AUC 选梯度提升 → 网格搜索调参 → 测试集用精确率/召回率/F1/AUC/混淆矩阵评估 → 换 LightGBM + OOF 定阈值 0.39 做 v2 → 全量重训、列对齐、预测验证集 5000 行输出两列 CSV。

**为什么这样做**：清洗防脏数据带偏模型；EDA 为特征解释和指标选择服务；交叉验证防一次划分碰运气；Pipeline 防数据泄漏；类别不平衡所以弃准确率、用 AUC 和召回率；电商漏判代价高所以优先召回率；阈值在训练集 OOF 上定防泄漏。

**评估优化好坏**：同一测试集同一口径比 AUC（整体区分能力，不依赖阈值）和 F1（精确率召回率平衡），并看混淆矩阵里 FP/FN 的实际变化——v2 AUC 0.9015→0.9053、F1 0.7753→0.7795、FN 少 13 人且 FP 不增，所以判定为有效但提升有限。
